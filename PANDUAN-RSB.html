Bagian I — Gambaran Umum

1. Apa itu RSB?

Ruang Strategi Belajar (RSB) adalah aplikasi web bimbingan belajar mandiri untuk siswa SMA/MA. Aplikasi ini dirancang untuk membantu siswa mengenali kebiasaan belajar mereka, menetapkan tujuan mingguan, mempraktikkan strategi belajar yang terbukti efektif, dan merefleksikan hasilnya — semua dengan pendampingan dari Guru BK sekolah.

Prinsip utama: data minimal, privasi siswa diutamakan. Siswa menentukan sendiri apa yang ingin dibagikan ke Guru BK. Tidak ada kata sandi untuk siswa, tidak ada iklan, tidak ada pelacak pihak ketiga.

Fitur Utama

Peran Fitur
Siswa Daftar dengan nama panggilan + kelas + kode sekolah · Persetujuan data · Kenali Kebiasaan · Tetapkan Tujuan · Jadwal Ulang Bertahap · Strategi Belajar & Kuis Mandiri · Fokus Belajar · Refleksi Mingguan · Ajukan Jadwal Konsultasi · Hapus Data Sendiri
Guru BK Login email & kata sandi · Dashboard siswa (filter kelas/hambatan) · Hanya data yang siswa izinkan · Kelola kode sekolah · Kelola jadwal konsultasi · Ubah status permintaan konsultasi
Admin Panel super admin · Tambah/hapus Guru BK · Lihat semua data · Preview tampilan siswa/guru · Edit konten teks halaman · Kelola kode & jadwal semua guru

Strategi Belajar yang Didukung

RSB mempromosikan strategi yang didukung riset (Dunlosky et al., 2013):

  • Latihan mengingat kembali — menjawab soal tanpa melihat catatan
  • Belajar terdistribusi — ulang materi pada hari ke-1, 3, 7, dan 14
  • Meringkas dengan kata sendiri
  • SQ3R — Survey, Question, Read, Recite, Review
  • Catatan Cornell

2. Arsitektur Aplikasi

RSB dibangun di atas dua komponen utama:

Next.js 15 (App Router)

Framework React dengan Server Components. Semua logika bisnis dan akses database berjalan di server — tidak ada secret yang bocor ke browser.

  • TypeScript
  • Server Actions untuk form
  • Middleware untuk autentikasi

Supabase (Backend)

PostgreSQL terkelola sebagai database, Supabase Auth untuk login Guru BK dan Admin. Semua tabel menggunakan RLS tanpa policy publik.

  • Service Role Key hanya di server
  • Row Level Security aktif
  • Anon Key hanya untuk inisialisasi

Alur Data

Browser → Server Action / Route Handler → Supabase (service role) → Database

Tidak ada request langsung dari browser ke Supabase untuk data sensitif. Semua melewati server Next.js yang memvalidasi sesi terlebih dahulu.

Sesi Siswa

Siswa tidak memiliki kata sandi. Sesi dibuat dengan token acak (crypto.randomBytes) yang disimpan di cookie httpOnly; SameSite=Strict. Hanya hash SHA-256 dari token yang tersimpan di database — sehingga data tidak bisa diidentifikasi ulang meskipun database bocor.

3. Peran Pengguna

Siswa

Daftar dengan nama panggilan, kelas, dan kode sekolah dari Guru BK. Tidak ada kata sandi. Data terikat ke perangkat yang digunakan mendaftar — gunakan perangkat yang sama untuk melanjutkan.

Guru BK

Login dengan email dan kata sandi yang dibuat oleh Admin melalui Panel Admin atau langsung di Supabase Dashboard. Guru BK hanya bisa melihat siswa yang terdaftar dengan kode sekolah miliknya.

Admin (Super Admin)

Akun admin dibuat manual di Supabase Auth, kemudian UUID-nya didaftarkan di tabel admins via SQL. Admin bisa mengelola semua Guru BK, melihat seluruh data, dan mengedit konten teks halaman utama.

Penting: satu project RSB bisa dipakai oleh banyak sekolah sekaligus. Setiap Guru BK memiliki kode sekolahnya sendiri, dan data antarsiswa dari sekolah berbeda tidak tercampur.

5. Buat Project Supabase

1
Buka supabase.com dan login atau daftar akun baru.
2
Klik New Project. Isi nama project (contoh: rsb-prod), pilih region terdekat (Singapore), dan buat database password yang kuat. Simpan password ini.
3
Tunggu project selesai di-provision (sekitar 1–2 menit).
4
Buka Project Settings → API. Catat tiga nilai berikut — akan dibutuhkan di langkah konfigurasi:
  • Project URL — contoh: https://abcdefgh.supabase.co
  • anon public key — kunci publik untuk inisialisasi client
  • service_role key — kunci rahasia, jangan dibagikan

6. Jalankan Skema Database

1
Di Supabase Dashboard, buka menu SQL Editor di sidebar kiri.
2
Buka file supabase/schema.sql dari folder project RSB, lalu salin seluruh isinya.
3
Paste di SQL Editor Supabase, lalu klik Run. Skema sudah menggunakan IF NOT EXISTS sehingga aman dijalankan berulang kali.
Yang dibuat oleh skema: tabel admins, site_content, counselors, school_codes, consult_slots, students, student_plans, quiz_attempts, reflections, consult_requests, practice_days — semua dengan RLS aktif.

7. Buat Akun Admin & Guru BK

Membuat Akun Admin

1
Di Supabase Dashboard, buka Authentication → Users → Add User.
2
Isi email admin (contoh: admin@rsb.sch.id) dan kata sandi. Klik Create User. Catat UUID user yang muncul.
3
Kembali ke SQL Editor, jalankan query berikut (ganti UUID dan nama): 
INSERT INTO admins (user_id, name)
VALUES ('xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx', 'Super Admin');

Membuat Akun Guru BK (via Panel Admin)

Setelah aplikasi berjalan, cara termudah adalah lewat Panel Admin (/admin):

1
Login ke /admin/masuk dengan akun admin.
2
Buka tab Guru BK, lalu isi form Tambah Guru BK Baru: nama, nama sekolah, email login, dan kata sandi awal.
3
Klik Tambah Guru BK. Sistem otomatis membuat akun di Supabase Auth, mendaftarkan ke tabel counselors, dan membuat satu kode sekolah awal.

Membuat Akun Guru BK (via SQL — alternatif)

Jika aplikasi belum jalan, buat akun Guru BK langsung di Supabase:

1
Buat user di Authentication → Users. Catat UUID-nya.
2
Jalankan di SQL Editor (ganti UUID, nama, nama sekolah, kode, dan catatan): 
INSERT INTO counselors (user_id, name, school_name)
  VALUES ('UUID_GURU', 'Ibu Sari', 'SMA Negeri 1 Jakarta');

INSERT INTO school_codes (code, owner_id, note)
  VALUES ('RSB-01', 'UUID_GURU', 'Kelas X-XII 2025');

INSERT INTO consult_slots (owner_id, label) VALUES
  ('UUID_GURU', 'Senin, 10.00 - 11.00'),
  ('UUID_GURU', 'Rabu, 13.00 - 14.00'),
  ('UUID_GURU', 'Jumat, 09.00 - 10.00');

Bagian III — Panduan Penggunaan

11. Alur Siswa

Berikut urutan lengkap penggunaan aplikasi dari sudut pandang siswa.

Langkah 0 — Mendapatkan Kode Sekolah

Sebelum mendaftar, siswa perlu meminta kode sekolah dari Guru BK. Kode ini berbentuk teks pendek (contoh: RSB-01) dan menghubungkan siswa ke akun Guru BK yang bersangkutan.

Langkah 1 — Pendaftaran (/daftar)

Siswa mengisi tiga hal:

  • Nama panggilan — maksimal 20 karakter, bukan nama lengkap
  • Kelas — X, XI, atau XII
  • Kode sekolah — dari Guru BK

Tidak ada kata sandi. Sesi terikat ke perangkat yang digunakan mendaftar via cookie terenkripsi.

Langkah 2 — Persetujuan Data

Sebelum mengakses fitur apapun, siswa membaca penjelasan tentang:

  • Data apa yang dicatat
  • Siapa yang bisa melihat
  • Jaminan keamanan dan minimalis
  • Fungsi aplikasi sebagai pendamping belajar

Siswa harus mencentang persetujuan dan klik Mulai untuk melanjutkan.

Langkah 3 — Perencanaan

3a. Kenali Kebiasaan (/siswa/kebiasaan)

Siswa mencentang kebiasaan belajar yang sudah dilakukan (dari dua kelompok: membantu dan menghambat), lalu memilih satu kebiasaan yang ingin dicoba atau ditingkatkan minggu ini.

Contoh kebiasaan membantu: menulis jadwal belajar, belajar sedikit-sedikit setiap hari.
Contoh kebiasaan menghambat: menunda sampai ujian dekat, belajar sambil membuka media sosial.

3b. Tetapkan Tujuan (/siswa/tujuan)

Siswa menuliskan satu tujuan spesifik untuk satu minggu ke depan. Tujuan yang baik menjawab: apa, kapan, dan berapa kali.

Contoh kurang baik: "Aku mau lebih rajin belajar."
Contoh baik: "Minggu ini aku menjawab 5 soal Matematika tanpa melihat catatan, Selasa dan Kamis pukul 19.00."

3c. Atur Waktu — Jadwal Ulang Bertahap (/siswa/waktu)

Siswa memilih tanggal belajar pertama dan materi yang ingin dipelajari. Aplikasi otomatis membuat jadwal pengulangan bertahap:

SesiJeda dari Belajar PertamaAktivitas
Belajar awalHari 0Pelajari materi baru
Ulang ke-1Hari 1Latihan mengingat kembali
Ulang ke-2Hari 3Latihan mengingat kembali
Ulang ke-3Hari 7Latihan mengingat kembali
Ulang ke-4Hari 14Latihan mengingat kembali

Jadwal bisa dicetak (Print) atau disalin ke buku catatan.

Langkah 4 — Pelaksanaan

4a. Strategi & Kuis (/siswa/strategi)

Siswa membaca penjelasan strategi belajar efektif, memilih strategi yang ingin dicoba minggu ini, lalu mengerjakan kuis mandiri 3 soal. Kuis tidak memiliki nilai — hanya untuk melatih ingatan. Jawaban boleh dicoba ulang sampai benar.

4b. Fokus Belajar (/siswa/fokus)

Siswa membuat rencana konkret mengurangi gangguan:

  • Apa yang dilakukan dengan notifikasi HP
  • Di mana tempat belajar
  • Alat apa yang perlu disiapkan sebelum mulai

Langkah 5 — Evaluasi

5a. Refleksi Mingguan (/siswa/refleksi)

Setelah satu minggu, siswa menjawab tiga pertanyaan:

  • Apa yang berhasil?
  • Apa kendalanya?
  • Apa penyesuaian untuk minggu depan?

Siswa juga memilih apakah hambatan belajarnya masih berlanjut dan apakah ingin berbicara dengan Guru BK.

Draf refleksi tersimpan otomatis di perangkat sehingga tidak hilang jika browser ditutup.

Deteksi kata kritis: jika teks refleksi mengandung kata-kata bernada putus asa (seperti "ingin mati", "bunuh diri"), aplikasi menampilkan pesan dukungan dan mengarahkan siswa ke halaman Bantuan Guru BK.

5b. Bantuan Guru BK (/siswa/bantuan)

Siswa bisa:

  • Memilih apakah ingin membagikan ringkasan ke Guru BK (ya/tidak)
  • Memilih apakah isi refleksi ikut dibagikan
  • Mengajukan jadwal konsultasi dari slot yang disediakan Guru BK
  • Melihat status permintaan konsultasi
  • Keluar dari perangkat ini
  • Menghapus semua data — tidak bisa dibatalkan

12. Alur Guru BK

Login (/guru/masuk)

Guru BK login dengan email dan kata sandi yang dibuat oleh Admin. Jika lupa kata sandi, Admin perlu mereset dari Panel Admin atau langsung di Supabase Dashboard (Authentication → Users).

Dashboard Guru BK (/guru)

Dashboard memiliki empat tab:

Tab Siswa

Daftar seluruh siswa yang terdaftar dengan kode sekolah milik Guru BK. Tersedia filter berdasarkan:

  • Kelas — X, XI, XII
  • Status hambatan — dari pilihan refleksi siswa

Untuk setiap siswa, terlihat:

  • Status refleksi (sudah/belum)
  • Hambatan belajar (hanya jika siswa membagikan)
  • Skor kuis terakhir (hanya jika siswa membagikan)
  • Jumlah hari berlatih bulan ini (hanya jika siswa membagikan)
  • Isi refleksi (hanya jika siswa mengizinkan)

Data yang tidak dibagikan siswa tidak terlihat — hanya muncul tanda "Tidak dibagikan".

Kolom Perlu perhatian muncul jika refleksi siswa mengandung kata-kata yang membutuhkan respons segera. Guru BK disarankan menghubungi siswa secara langsung.

Tab Konsultasi

Daftar semua permintaan jadwal konsultasi dari siswa. Guru BK bisa mengubah status setiap permintaan:

  • Baru — permintaan baru masuk
  • Dijadwalkan — sudah dikonfirmasi waktunya
  • Selesai — konsultasi sudah berlangsung

Tab Kode Sekolah

Guru BK bisa:

  • Melihat semua kode sekolah yang dimiliki
  • Menyalin kode untuk dibagikan ke siswa
  • Menonaktifkan kode yang sudah tidak dipakai (siswa baru tidak bisa mendaftar)
  • Membuat kode baru (contoh: untuk angkatan baru)

Menonaktifkan kode tidak menghapus siswa yang sudah terdaftar.

Tab Jadwal

Guru BK mengelola slot jadwal konsultasi yang tersedia untuk siswa. Slot yang aktif akan muncul di halaman Bantuan Guru BK di sisi siswa.

Contoh format jadwal: "Jumat, 10.00 – 11.00"

Slot bisa dinonaktifkan sementara tanpa dihapus.

Tips untuk Guru BK

  • Bagikan kode sekolah di awal semester atau saat sesi bimbingan kelompok.
  • Minta siswa untuk mengisi refleksi mingguan setiap Jumat atau akhir minggu.
  • Pantau kolom "Perlu perhatian" setiap hari Senin sebagai rutinitas mingguan.
  • Jika kode sekolah lama sudah tidak aktif, buat kode baru untuk semester berikutnya agar data lama tetap tersimpan.

13. Panel Admin

Panel Admin dapat diakses di /admin setelah login di /admin/masuk.

Tab Overview

Ringkasan seluruh sistem: jumlah Guru BK, total siswa, siswa yang sudah consent, kode aktif, jumlah refleksi, dan permintaan konsultasi. Tersedia shortcut untuk masuk ke tampilan Guru BK atau Murid tertentu tanpa perlu login ulang.

Tab Lihat View Guru & Murid

Admin bisa mensimulasikan tampilan persis seperti yang dilihat Guru BK atau siswa tertentu. Banner ungu akan muncul di bagian atas halaman, menandakan mode preview. Admin bisa kembali ke Panel Admin kapan saja tanpa mengganggu sesi asli pengguna tersebut.

Tab Guru BK

Daftar semua Guru BK beserta detail kode sekolah dan jadwal konsultasi miliknya. Admin bisa:

  • Menambah Guru BK baru (nama, sekolah, email, kata sandi awal)
  • Menghapus Guru BK beserta semua datanya
  • Menambah/menonaktifkan kode sekolah untuk Guru BK tertentu
  • Menambah/menonaktifkan jadwal konsultasi

Tab Siswa

Daftar semua siswa dengan detail progres lengkap — terlepas dari pengaturan privasi siswa. Filter berdasarkan kelas dan kode sekolah. Admin bisa menghapus satu siswa atau semua siswa dari kode tertentu.

Tab Konsultasi & Refleksi

Melihat semua permintaan konsultasi dan refleksi terbaru dari seluruh sekolah. Admin bisa mengubah status permintaan konsultasi.

Tab Edit Konten

Admin bisa mengubah teks yang tampil di halaman utama tanpa menyentuh kode:

  • Judul dan subjudul halaman utama
  • Teks keempat badge di hero section
  • Intro halaman Strategi Belajar
  • Teks footer

16. Keamanan & Privasi

Row Level Security (RLS)

Semua tabel mengaktifkan RLS tanpa policy publik. Artinya tidak ada akses langsung dari browser ke database — seluruh akses data melewati server Next.js menggunakan service role key.

Sesi Siswa

  • Token dibuat dengan crypto.randomBytes(32)
  • Hanya hash SHA-256 yang disimpan di database
  • Token asli ada di cookie httpOnly; SameSite=Strict
  • Tidak ada kata sandi yang perlu diingat atau bisa dicuri

Isolasi Data Guru BK

Guru BK hanya bisa melihat siswa yang terdaftar dengan kode sekolah miliknya. Query selalu difilter berdasarkan owner_id yang dicocokkan dengan sesi guru yang login.

Kontrol Privasi Siswa

  • Guru BK hanya melihat data yang siswa aktifkan via toggle Bagikan ringkasan
  • Isi refleksi hanya terlihat jika siswa mengaktifkan Sertakan refleksi
  • Siswa bisa mencabut izin berbagi atau menghapus semua datanya kapan saja

Variabel Environment

SUPABASE_SERVICE_ROLE_KEY tidak boleh memiliki awalan NEXT_PUBLIC_. Jika salah diberi awalan tersebut, kunci ini akan terekspos di JavaScript bundle yang dikirim ke browser.

17. Keterbatasan & Catatan

Sesi Siswa Tanpa Kata Sandi

Data siswa terikat ke perangkat dan browser yang digunakan mendaftar. Jika ganti perangkat, hapus cookie, atau ganti browser, siswa perlu mendaftar ulang dan data lama tidak bisa diakses lagi. Solusi lanjutan: sistem kode pemulihan.

Deteksi Kata Kritis

Deteksi kata bernada putus asa menggunakan regex sederhana yang ditetapkan di src/lib/constants.ts:

export const CRISIS =
  /bunuh diri|mengakhiri hidup|ingin mati|pengen mati|
   menyakiti diri|melukai diri|putus asa/i;

Daftar kata ini sebaiknya ditinjau dan disepakati bersama Guru BK sekolah. Aplikasi bukan layanan krisis dan tidak membalas pesan.

Tidak Ada Pembatasan Percobaan Login

Belum ada rate limiting khusus untuk login Guru BK di luar bawaan Supabase. Untuk produksi, pertimbangkan menambahkan Cloudflare Turnstile atau mekanisme serupa.

Retensi Data

Belum ada kebijakan penghapusan data otomatis berkala. Untuk kepatuhan privasi, pertimbangkan menetapkan batas retensi data (misal: hapus akun siswa yang tidak aktif lebih dari 1 tahun).

Persetujuan Institusional

Untuk penggunaan di sekolah nyata, persetujuan dari pihak sekolah serta orang tua/wali siswa tetap diperlukan, terlepas dari mekanisme persetujuan digital yang ada di aplikasi.

Belum Diuji di Produksi

Aplikasi ini telah lolos typecheck dan build lokal, namun belum diuji secara menyeluruh dengan database Supabase sungguhan di lingkungan produksi. Lakukan pengujian menyeluruh sebelum digunakan di sekolah.
